# XDream Cloud 前端视觉系统第一阶段设计

## 目标

第一阶段将现有控制台收敛为一套适合高频、长时间使用的专业运维界面。改造基于现有 Next.js、React、Tailwind 和 shadcn 技术栈，不改变业务流程、接口或数据模型。

本阶段覆盖：

- 登录页
- 全局导航、顶栏、页面标题和响应式布局
- shadcn 设计令牌与共享交互组件
- 虚拟 Office
- 训练作业
- CMDB

其余云桌面、Isaac、存储管理、推理部署和集群管理继续使用兼容的共享壳层，后续阶段再逐页收敛内部布局。

## 约束

- 普通笔记本电脑是首要桌面目标，重点验证 `1366x768` 和 `1440x900`。
- 不修改远程机器上的代码。
- 不改变 Kubernetes 配置；页面需要展示集群信息时，只读取 `infra/k8s/cluster`。
- CMDB 与 Kubernetes 保持业务隔离，视觉改造不能引入二者之间的数据或操作耦合。
- 保留现有权限、认证、tRPC 调用、任务操作、表单字段和状态转换。
- 第一阶段不做无关的服务端重构。

## 候选方向

### 方案 A：Quiet Operations Console（采用）

以浅灰工作画布、白色数据表面和深炭色导航构成稳定框架。蓝色只用于主操作，琥珀色只用于当前位置，绿、红、黄用于状态语义。界面减少渐变、光晕和层叠卡片，通过边框、间距、分隔线和排版建立层级。

优点是长时间使用疲劳较低、信息密度高、适合普通笔记本，并且能够用 shadcn 组件稳定落地。代价是视觉表现更克制，需要依靠排版和细节而不是装饰制造质感。

### 方案 B：Monochrome Data Desk

使用接近黑白的配色和更高密度表格，把绝大部分空间交给数据。它对训练任务和 CMDB 很有效，但会削弱虚拟 Office 的空间感与产品识别，也不利于快速区分主操作和状态。

### 方案 C：Dark Command Center

全局使用深色背景、发光状态和高对比图表，视觉冲击力强。它更适合短时监控大屏，不适合白天办公和长时间处理表单，复杂页面的可读性和维护成本也更差。

方案 A 在效率、审美、可维护性和跨模块适配之间最平衡，因此作为第一阶段基线。用户已授权后续均采用推荐方案，无需逐项确认。

## 视觉系统

### 色彩

- 页面画布：中性浅灰，弱化当前网格和大面积渐变。
- 内容表面：白色或近白色，只在真正需要边界的工具、表格、对话框和重复条目上使用。
- 导航：深炭灰而非蓝黑渐变，避免页面被单一冷色主导。
- 主操作：清晰的中等蓝色，保持足够对比度。
- 当前导航：克制的琥珀色标记，不作为普通装饰色。
- 状态：成功、警告、危险和信息分别使用稳定的绿、黄、红、蓝语义，不把状态色用于无关区域。

### 排版

- Geist 用于正文和界面，Manrope 只用于页面级标题。
- 页面标题保持 `24–28px`，紧凑面板标题保持 `14–18px`。
- 字距固定为 `0`；仅产品标识和少量英文 eyebrow 使用正字距。
- 说明文字优先短句，关键数值与标签紧邻，避免卡片内出现大段操作说明。

### 形状和阴影

- 控件圆角 `6px`，内容表面和对话框圆角 `8px`。
- 不使用卡片套卡片；页面区段优先无框或使用单层边框。
- 阴影只用于侧栏、悬浮菜单、对话框和粘性顶栏，普通卡片依靠边框分组。

### 密度

- 默认按钮高度 `36px`，主要创建按钮可使用 `40px`。
- 表格行高约 `44–48px`，工具栏和筛选器使用紧凑尺寸。
- 指标卡改为单一连续的指标带，减少四张独立卡片造成的空间和视觉浪费。

## 全局布局

### 桌面与笔记本

- `>=1280px`：使用约 `216–224px` 的完整侧栏，保留图标、中文名称和短标签。
- `768–1279px`：收为约 `64–68px` 图标栏，所有图标提供 shadcn Tooltip，主内容不横向溢出。
- `<768px`：使用顶栏菜单按钮和 shadcn Sheet 导航，不把桌面侧栏压缩到移动视口。
- 内容区占满可用空间，页面内部根据业务使用合适的最大宽度；数据表和虚拟 Office 不人为收窄。

### 导航

- 产品标识、分组导航和用户菜单形成三个稳定区域。
- 导航分为“工作区”和“平台”两组，保持现有路由顺序。
- 当前项使用左侧琥珀标记和轻微底色；非当前项不显示彩色圆点和持续动画。
- 用户信息改为 DropdownMenu，集中放置角色信息和退出操作。

### 顶栏与页面头部

- 粘性顶栏承载移动菜单、面包屑和跨页工具，不重复业务页面说明。
- 页面标题采用无框布局：标题、简短描述、状态与主要动作处在同一层级。
- 每页只保留一个视觉主操作，其余动作使用 outline、ghost 或 DropdownMenu。

## shadcn 组件策略

继续使用现有 `base-nova` 配置，优先通过 shadcn CLI 引入或校准以下组件：

- `Button`、`Badge`、`Input`、`Textarea`、`Select`
- `Tabs`、`Table`、`Tooltip`、`DropdownMenu`
- `Dialog`、`AlertDialog`、`Sheet`、`ScrollArea`
- `Skeleton`、`Alert`、`Toast`

共享业务组件保持薄封装：

- `AppSidebar`：产品导航、响应式收起和移动 Sheet。
- `AppTopbar`：面包屑、全局工具和移动入口。
- `PageHeader`：标题、描述、状态与主要动作。
- `MetricStrip`：连续指标带，支持 2/4 列响应式布局。
- `DataToolbar`：搜索、筛选、Tabs 和批量动作。
- `StatusBadge`：统一状态文案和颜色映射。
- `EmptyState`：空数据、失败和权限不足的统一呈现。

这些组件只统一呈现和交互，不吸收各模块的业务状态或 API 调用。

## 模块设计

### 登录页

- 桌面保留双区结构，但降低深色区域的网格、光晕和装饰强度。
- 登录操作区缩短说明，强化飞书登录这一唯一主操作。
- 移动端改为单一无嵌套表面，确保 `390x844` 首屏完整显示品牌、说明和按钮。
- 保留登录错误 Toast、回跳路径和认证行为。

### 虚拟 Office

- 以 Office 画布作为主体验，移除占用首屏高度的大型介绍区和重复统计卡。
- 页面头部仅保留当前运行状态、核心筛选和主操作。
- Agent、任务和审批的摘要使用紧凑指标带；画布占据余下的主要可视高度。
- 选中 Agent 或任务的详情使用右侧 Sheet 或现有面板，避免在画布上叠加多个卡片。
- 保留实时流、Agent 选择、任务操作和 workspace 路由行为。

### 训练作业

- 页面结构为：标题与创建操作、指标带、筛选工具栏、任务表格。
- 状态筛选使用 Tabs，搜索和高级筛选位于同一工具栏。
- 表格优先显示任务、状态、运行环境、GPU、更新时间和行操作；较窄视口隐藏次要列并提供详情入口。
- 创建和编辑使用 Dialog，任务详情使用右侧 Sheet；保留现有操作，不新增日志或集群数据调用，也不改变提交数据。
- 错误信息靠近表格区域展示，同时保留 Toast 作为动作反馈。

### CMDB

- CMDB 保持与 Kubernetes 完全独立。
- 服务器资产、GitLab 项目、部署记录等现有视图使用一致 Tabs 和 DataToolbar。
- 默认视图优先表格与扫描效率，详情使用右侧 Sheet，创建与编辑使用 Dialog，危险操作统一使用 AlertDialog。
- 长表单按身份、连接、部署配置等语义分区，减少单个超大表单中的视觉噪声。
- 保留现有 SSH、部署、日志、项目和资产操作；第一阶段只整理呈现层和局部组件边界。

## 数据流和状态

- 服务端页面、tRPC query/mutation 和本地状态来源保持不变。
- 共享视觉组件通过 props 接收文案、状态和动作，不直接发起请求。
- 现有模块 shell 继续拥有业务状态；第一阶段在需要时提取纯呈现子组件，避免一次重写 8,000 行 CMDB 逻辑。
- 任何集群展示数据继续从 `infra/k8s/cluster` 或现有服务端 API 获取，不在前端复制集群事实。

## 错误、加载和空状态

- 初始加载使用与最终布局同尺寸的 Skeleton，避免布局跳动。
- 页面级读取失败使用 Alert，并保留重试动作；动作级失败使用 Toast。
- 空列表使用紧凑 EmptyState，包含一个明确主操作，不使用大面积虚线装饰框。
- 权限不足、连接失败和真实空数据必须使用不同文案与状态图标。
- 对话框提交期间禁用重复提交，并在原按钮中显示加载状态。

## 可访问性

- 图标按钮提供可访问名称和 Tooltip。
- 键盘焦点使用 shadcn ring，不以颜色作为唯一状态信号。
- 导航、Tabs、表格操作和对话框保持语义结构与键盘操作。
- 正文和控制文字满足常规对比度，状态 Badge 同时保留文字。
- 尊重 `prefers-reduced-motion`，移除当前侧栏持续扫描动画。

## 测试与体验验收

### 自动检查

- 运行格式检查、TypeScript、ESLint 和生产构建。
- 保持现有业务单元测试通过。
- 为新共享组件的状态映射和响应式布局辅助逻辑补充聚焦测试。

### 浏览器体验

使用真实浏览器检查：

- `1366x768`：完整侧栏可读，主要操作和首批数据无需横向滚动。
- `1440x900`：页面密度平衡，Office 画布获得主要高度。
- `1024x768`：图标栏、Tooltip、表格缩列和对话框均可用。
- `390x844`：Sheet 导航、登录、表单和主要动作不重叠、不溢出。

逐页验证登录、导航、虚拟 Office、训练作业和 CMDB 的核心查看与操作路径，并检查浏览器控制台错误、网络失败反馈、焦点状态和动态内容是否造成布局跳动。

## 非目标

- 不重写后端服务、数据库或 Kubernetes 部署。
- 不改变 CMDB 与其他模块的业务边界。
- 不在第一阶段全面重构云桌面、Isaac、存储、推理和集群页内部布局。
- 不引入新的动画框架、图表系统或品牌图片资产。
- 不为视觉统一而删除现有功能。
